# Soup Kernel Challenge: памятка для сессии-оркестратора

Этот файл читает Claude Code при открытии папки. Он заменяет память предыдущего оркестратора: прочитай его, затем `docs/STATUS.md` (текущие числа и что в работе), `docs/TASKS.md` (задачи и границы), `README.md` (правила организаторов и 10 проверок).

## Что за задача

Decentrathon 6.0, трек 01 Soup Kernel Challenge, дедлайн 31 октября 2026 23:59 по Астане. Фиксированный прогон `soup train` (Qwen2.5-1.5B-Instruct в NF4, LoRA r=16 на q_proj и v_proj, batch 4, до 512 токенов, 64 шага). Харнесс на Kaggle T4 запускает базовый Soup и Soup с нашим пакетом `solution/` (`apply()` патчит transformers, peft, bitsandbytes, trl) и меряет время всей команды и пик памяти nvidia-smi. Баллы: 20 за все 10 проверок (иначе 0), 35 за скорость, 30 за память, 15 за README. Скорость = 35·ln(s)/ln(s лучшей команды), память = 30·ln(m)/ln(m лучшей), выигрыш меньше 5% считается нулём, при равной сумме выше тот, у кого память лучше. Жюри гоняет базу и решение по два раза на скрытых строках с другим seed. Матмулы остаются в cuBLAS: Triton 3.6 на T4 (sm_75) не использует тензорные ядра, свои ядра только для поэлементных операций, редукций, распаковки и loss.

## Роль оркестратора

Ты не пишешь код сам, кроме интеграции в `solution/__init__.py`, правок своих файлов (`unpad.py`, `fused_ce.py`, docs) и мелочей. Код, тесты и гипотезы делают подчаты (nested sessions) на Opus 5.5 с effort xhigh, каждый в своём worktree и ветке, с брифом по образцу `docs/TASKS.md`: файлы только свои, тесты рядом, микробенчмарк, проверка `check_rules.source_kernels`, в конце `git push -u origin <ветка>`, отчёт до 300 слов. Ты ревьюишь отчёт, вливаешь ветку в main (`git merge origin/<ветка>`), подключаешь в `apply()` за переменной окружения `SOUP_SOLUTION_<ИМЯ>=0/1`, гоняешь тесты и Kaggle, пишешь строку в таблицу `docs/STATUS.md`, пушишь. Подчатам можно писать по ходу (их sessionId в боковой панели), например целевые числа из профиля. Решения о направлении принимай по измерениям на T4, не по локальной карте.

## Среда и команды

Локально нужен Linux или WSL2 с картой NVIDIA: `python -m venv` или uv с Python 3.11–3.13, затем `pip install "soup-cli[train]==0.77.0" "transformers==5.16.1" "peft==0.20.0" "trl==0.29.1" "bitsandbytes==0.50.2" "accelerate==1.14.0" pytest`; torch 2.11 и triton 3.6.0 подтянутся зависимостями (это версии Kaggle). Triton собирает лаунчер компилятором C: `sudo apt-get install build-essential` или обёртка `zig cc` из пакета `ziglang` через переменную CC. Первый запуск: `python task/prepare_data.py`, `python -m pytest solution -q`, `SOUP_APPLY_SOLUTION=1 python -m pytest tests -q` (79 тестов Soup должны пройти). Полный `soup train` локально требует 8 ГБ для нашего решения (база 14 ГБ не влезет), числа с локальной карты не сравнимы с T4.

Kaggle из консоли: `pip install kaggle`, токен из kaggle.com/settings/api в переменной `KAGGLE_API_TOKEN` (аккаунт с подтверждённым телефоном, иначе сессии без GPU). Секреты Kaggle к ноутбукам, запущенным через API, не цепляются, поэтому токен GitHub для приватного репозитория лежит в приватном датасете `<логин>/soup-secrets` (создаётся командой `python tools/kaggle_run.py --user <логин> --setup-secrets --github-token-file <файл>`; токен GitHub только на чтение репозитория). Прогон: `python tools/kaggle_run.py --user <логин> --repo https://github.com/BAITC-Hacks/hack-78c6e9c3-null-pointers.git --commit HEAD --mode full [--repeats 2] [--mode profile]`, около 7 минут на полный прогон, 25 на два повтора; результаты и логи в `runs_kaggle/<дата>-<режим>-<slug>/output/`, краткая сводка и 10 проверок печатаются в конце. Параллельные прогоны с одного аккаунта: разные `--slug`. На момент написания рабочий аккаунт namedesign; peagverr без GPU.

## Правила, которые нельзя нарушить

Не менять `harness/`, `tests/`, `task/`. Не менять задачу: модель, данные, порядок батчей, число шагов, LoRA, оптимизатор, переключатели Soup (gradient_checkpointing, activation_offloading, fast_lora, use_cut_ce, packing, padding_free, stream_layers, backend unsloth, use_liger). Запрещены unsloth, liger, xformers, flash-attn, torchao и остальное из `BANNED_MODULES` в `harness/common.py`, CUDA graphs для своих ядер, torch.compile как «свои ядра», подмена адаптера, готовые кэши компиляции. Ядра примера `solution/swiglu.py` своими не считаются ни под каким именем; похожесть по AST с ними выше 0,8 читает жюри. Каждый патч откатывается на оригинал при неожиданном входе (тесты Soup вызывают патченый код с фальшивыми модулями). Данные и `runs*/` в репозиторий не класть.
