# Задание для Codex (GPT-6.1 Sol или GPT-6 Astra): независимое ревью и поиск времени

Репозиторий: https://github.com/BAITC-Hacks/hack-78c6e9c3-null-pointers (ветка `main`, коммит a6c3fe3 или новее). Это наше решение трека «Soup Kernel Challenge» (Decentrathon 6.0). Прочитай по порядку: `CLAUDE.md`, `README.md` (правила, 10 проверок, формула баллов), `docs/RULINGS.md` (разъяснения организаторов), `docs/STATUS.md` (верхние разделы: что сделано ночью и измерения), `docs/RESEARCH.md` (что измерено и отвергнуто), `docs/notes/*.md`, затем код `solution/` (точка входа `solution/__init__.py::apply`), `harness/_train.py`, `harness/check_rules.py`, `harness/common.py` (харнесс менять нельзя, он эталон).

Контекст в двух фразах: фиксированный прогон `soup train` (Qwen2.5-1.5B NF4, LoRA r=16, batch 4, 64 шага) на Kaggle T4 меряется по стене всего процесса и пику nvidia-smi против базового Soup; у нас 42.7 с / 401 MiB против базы 87 с / 14 345 MiB, все 10 проверок; соперник заявляет 29 с / 937 MiB; точка перелома для нас 36 с при 401 MiB. Баллы: 35·ln(s)/ln(s_best) за время, 30·ln(m)/ln(m_best) за память, 20 за проверки (иначе ноль), 15 README.

## Что нужно от тебя

Работай в ветке `codex/review-1`. Ничего не меняй в `harness/`, `tests/`, `task/`. Правки в `solution/` только за переключателями `SOUP_SOLUTION_<ИМЯ>` с откатом на оригинал при неожиданном входе и с тестами рядом (`solution/test_*.py`). Выходы обучения должны остаться побитово теми же, если ты явно не обосновал допуск (проверки 5–7). Результат: файл `docs/notes/codex-review.md` и коммиты в ветке.

1. **Поиск дефектов, которые дадут ноль у жюри.** Жюри гоняет базу и решение по два раза на скрытых строках (до ~2 000 токенов в шаге) с другим seed. Проверь на устойчивость: все откаты патчей при фальшивых модулях (79 тестов Soup: `SOUP_APPLY_SOLUTION=1 python -m pytest tests -q`), пути с оффлоадом по событиям (`solution/offload.py`), стриминг весов (`solution/weight_stream.py`, кольцо по типам матриц), потоковую голову (`solution/head_stream.py`), пересчёт attention (`solution/fused_proj.py`, `solution/unpad.py`), загрузчик через pinned-буферы (`solution/load_pinned.py`, `solution/load_stream.py`), прогрев в потоке (`solution/warmup.py`, выход процесса), лимит стека (`solution/cuda_limits.py`). Особенно: гонки потоков и событий, порядок потоков при аллокации (аллокатор харнесса `expandable_segments`), проверка 9 (пик nvidia-smi должен быть ≥ 0.97 × reserved torch: любой короткий всплеск reserved, не увиденный опросом nvidia-smi, даёт ноль), коды выхода, поведение при длине шага больше публичной, при `max_length` граничных строках, при OOM на хосте (pinned 4.3 ГБ).
2. **Поиск времени.** Профилируй мысленно и по коду CPU-путь шага: где Python делает лишнее на каждом слое и каждом шаге (чтения атрибутов через `Params4bit.__torch_function__`, события, запуски, autograd.Function), и граница шага (синхронизации `.item()`, проходы Trainer по модели, SQLite-трекер Soup, DataLoader). Предложи и, где уверен, реализуй за переключателями конкретные сокращения с оценкой мс/шаг. Также посмотри старт: `solution/startup.py`, `solution/trainer_build.py`, импорты в `apply()` (bitsandbytes тянет torch._dynamo/inductor 1.1 с; trl 0.9 с; transformers.data 0.4 с), щель между `apply end` и `setup_transformers begin` (0.6 с, Soup CLI), и завершение процесса (0.9 с после метки `exit`: освобождение pinned-памяти, контекст).
3. **Идеи, которых у нас нет.** Мы три дня работали агентами одной модели. Назови механизмы снижения времени и памяти на T4 для этой задачи, которые отсутствуют и в `solution/`, и в списке отвергнутого в `docs/RESEARCH.md`, с оценкой выигрыша и риска для проверок.

## Ограничения и факты, чтобы не терять время

- GEMM остаются в cuBLAS (Triton 3.6 на sm_75 без тензорных ядер в `tl.dot`); T4 упирается в лимит мощности 70 Вт (28–34 TFLOPS реально), распаковка NF4 на 88 % полосы, PCIe ~12 ГБ/с.
- Запрещены: unsloth/liger/xformers/flash-attn/torchao, CUDA graphs для своих ядер, torch.compile как «свои ядра», `sys.modules`-заглушки, `os._exit`, фоновые процессы (потоки можно), кэши между прогонами, смена аллокатора/гиперпараметров/батчей, общая маска для метрик (entropy по attention_mask без сдвига; loss/accuracy/rewind по сдвинутым labels с −100). int8 в backward готов (`solution/int8_bwd.py`), но выключен до ответа организаторов.
- Локально без T4 числа не сравнимы; на Kaggle прогон делается `python tools/kaggle_run.py --user <логин> --repo <url> --commit <sha> --mode full` (нужен токен Kaggle и приватный датасет с токеном GitHub, см. `CLAUDE.md`). Если Kaggle недоступен, ограничься кодом и тестами и пометь оценки как неизмеренные.
