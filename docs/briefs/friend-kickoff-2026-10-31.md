## 4. Правила, которые нельзя нарушить (иначе 0 за всё)

- Всё из `CLAUDE.md` и RULINGS. Свежие запреты: **никак не менять вычисление отпечатка datasets** (ответы 8, 9, 13: даже побайтно тот же быстрый пикл нельзя; `FAST_ROWS` выключен по той же причине), **не трогать сборщик мусора** и явные `gc.collect()` библиотек (10, 31), без `sys.modules`-заглушек, `os._exit`, процессов-помощников, своего RNG для dropout, `PRAGMA synchronous`.
- **Одинаковое поведение в замере и в тестах** (README: «different behaviour when measured or tested» = обход замера): никаких включений по `sys.argv`/имени процесса. Побитовые тесты fp16-пути фиксируют исходный путь в `solution/conftest.py`; у оптимизированных путей — свои тесты.
- Запрещённые приёмы удалять из кода, а не только выключать: жюри читает код руками.
- Точность важнее скорости: вливать только с запасом — full и два jury-прогона на разных seed, |Δeval| ≤ 0,2 %, кривые ≤ 0,5 %, первый шаг ~0,01 %, пик ≤ 450 MiB.
- Новый серый приём — за выключенным переключателем, пока организаторы не ответят; формулировку вопроса передай Абзалу.

## 5. Брифы для Астры

Астра (GPT-6 Astra Pro, чат, читает до ~200 тыс. символов, думает 15–20 минут) сильна в поиске слепых пятен и новых идей с расчётами. Когда у тебя есть вопрос, который стоит её внимания (дизайн MMA-тайла под T4 и раскладка фрагментов в Triton, путь B из брифа B3, где ещё прячутся секунды при наших ограничениях, разбор твоих замеров), собери бриф по образцу `docs/briefs/astra-brief-4-2026-10-31.md`: в начале самодостаточный заголовок (задача, правила, текущие числа с T4, что уже сделано и отвергнуто, конкретные вопросы с просьбой давать механизм, мс/шаг, память, риск, проверку за час), затем приложение из документов и, если нужно, кода. Клади в `docs/briefs/astra-brief-<N>-<тема>-2026-10-31.md`, пушь и скажи Абзалу; ответ он положит в `astra-answer-<N>-....md`.
