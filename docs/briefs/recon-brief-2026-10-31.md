# Разведка трат: куда уходит каждая секунда `soup train` (бриф для Claude Code тиммейта)

Ты работаешь самостоятельно в клоне `BAITC-Hacks/hack-78c6e9c3-null-pointers` на свежем `main`, в своей ветке `claude/recon-<твоё имя>`. Задача — **разведка, не реализация**: полная и проверяемая карта того, на что тратится стена нашего прогона, с числами T4, и ранжированный список «мусорных» трат, которые можно убрать по правилам. Используй субагентов (инструмент Agent) для параллельных разборов; итог свожу я (сессия Абзала) и раздаю подчатам, которые делают реализацию.

## Что уже известно (не переоткрывать, а уточнять)

- main ≈ 43,7 с при базе 81 (s ≈ 1,85), пик 395 MiB, 10 из 10. Пролог харнесса до `apply()` ~5,6 с (не наш), от `apply begin` до первого шага ~10,8 с (импорты 3,3; загрузка модели до +3,2; сборка тренера ~3,8, из них dill-хеш токенизатора 1,3–2,9 с — **трогать вычисление отпечатка datasets запрещено**; прогрев Triton ~5 с параллельно), цикл 64 шагов ~26–28 с, хвост ~0,3 с.
- Трасса шага (P2, `tools/trace_waits.py` в ветке `origin/claude/p2-pcie-critical`): на публичных строках вычислительный поток простаивает ~129 мс/шаг, из них **~97 мс — CPU ещё не поставил следующее ядро** (56 в forward, 41 в backward), копии ~26 мс; на строках как у жюри простой ~35 мс/шаг.
- Профиль ядер: ~2 750 запусков ядер на шаг (было ~2 090 до int8-путей), 1 304 мелких поэлементных ядра torch, 28 `floor` + 85 `clamp` на шаг; харнесс оборачивает каждый запуск наших Triton-ядер двумя CUDA-событиями.
- Соперник с 574 MiB: 37,8 с при базе 83,7 при цикле как у нас — разница в старте.

Уже в работе у подчатов (не дублировать реализацию, но разведку по этим зонам делать можно и нужно): L2 — старт (спекулятивная NF4-загрузка, меньше вариантов ядер через `do_not_specialize`, пониженный приоритет потока компиляции — разрешён организаторами), I1 — CPU-сторона шага, H1 — слияние мусорных ядер (`floor`/`clamp`/копии), P2 — расписание копий.

## Что сделать

1. **Старт по потокам и по функциям.** Один прогон с профилем старта (`SOUP_SOLUTION_PROFILE_STARTUP=1`, `solution/startup_profile.py`; фазы `[solution] phase` в train.log): для главного потока и каждого фонового — что выполняется, сколько под GIL, сколько ждёт; критический путь от `apply begin` до первого шага; что из этого — работа Soup/transformers/datasets, которую мы обязаны оставить, а что — наше и лишнее.
2. **CPU шага по местам вызова.** `SOUP_SOLUTION_CPU_PROFILE=1` (`solution/cpu_profile.py`): на коротком (<600 токенов) и длинном шаге — время Python на слой и проход по функциям; сколько запусков ядер, событий, `wait_event`, `torch.cuda.stream()`/`current_stream()`, `__torch_function__`, `.item()`/синхронизаций; что из этого можно убрать или сделать один раз.
3. **GPU-трасса** (CUDA-only, как у P2): категории пауз по корзинам длины, отдельно forward/голова/backward/оптимизатор/граница шага.
4. **Хвост и граница шага:** что происходит между последним шагом и выходом процесса; что делается на каждом шаге вне forward/backward (метрики, логи, трекер SQLite, rewind, оптимизатор).
5. **Сравнение с базой там, где это помогает понять лишнее:** какие операции базы мы повторяем без нужды.

Субагентам давай узкие задания (одна зона, конкретные файлы и логи), итог каждого — таблица «трата → мс на шаг или с за прогон → чья (наша / Soup / харнесс) → можно ли убрать по правилам → как». Не включай в итог то, что запрещено (`docs/RULINGS.md`): изменение отпечатка datasets, своя токенизация без map, правки GC/`setswitchinterval`, `sys.modules`-заглушки, `os._exit`, процессы-помощники, свой RNG для dropout, обход `JITFunction.run`, разное поведение в замере и тестах.

Прогоны: `python tools/kaggle_run.py --help` (режимы `full`, `diag`, `profile`, `variants`, `--skip-pytest`, `--env`), обёртки `tools/kaggle_win.sh` / `tools/kaggle_wsl.sh`. **Используй свой собственный аккаунт Kaggle** (с подтверждённым телефоном и своим приватным датасетом `<логин>/soup-secrets`, команда настройки в `CLAUDE.md`): аккаунты namedesign / peagverr / slerfas заняты сессиями Абзала, и третий ноутбук на аккаунте убивает соседний прогон.
