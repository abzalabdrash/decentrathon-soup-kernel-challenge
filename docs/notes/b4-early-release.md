# B4: раннее освобождение NF4-слотов в int8 backward MLP (31 октября, вечер)

Ветка `claude/b4-early-release` от main 45705ab. Находка из ответа Астры на бриф 5 (полная версия), проверена по коду.

## Что было

`fused_proj._MLP.backward`, int8-путь (main 45705ab, `solution/fused_proj.py:1674-1679`): захватывает слоты кольца весов для down, gate и up, выполняет весь `int8_bwd.mlp_backward` и только потом отпускает все три. Но последнее чтение 4-битных весов в `int8_bwd.mlp_backward` происходит раньше: down читается в `_column_scales` и `_decode_t` перед первым `_int_mm` (строки 311-313), gate и up перед вторым (строки 335-341); GEMM-ы читают распакованную int8-копию в общем буфере, а не слот. `WeightStreamer.release` (`weight_stream.py:799-809`) запускает копию той же матрицы следующего слоя в этот слот (`_load`: событие `_free` на вычислительном потоке после всего уже поставленного, копирующий поток ждёт его). Значит, копия весов следующего слоя стартовала только после всего int8 backward текущего слоя.

## Что сделано

`SOUP_SOLUTION_EARLY_RELEASE=1`: `int8_bwd.mlp_backward(..., release=...)` вызывает `release(plan.down)` сразу после `_decode_t` down (до первого int8 GEMM), `release(plan.gate)` и `release(plan.up)` сразу после их `_decode_t` (до второго). `fused_proj` передаёт колбэк, который зовёт `ring.release(base, -1)`, и в конце отпускает только то, что не отпущено раньше (каждая матрица ровно один раз). Вычислительный поток выполняет те же ядра в том же порядке, значения те же; меняется только момент старта копии на копирующем потоке. Память та же (слоты те же). По умолчанию выключено до замера.

Тесты `solution/test_early_release.py` (локально 4 прошли, соседние `test_int8_bwd`, `test_weight_ring`, `test_offload_int8`, `test_fused_proj` 71 прошли): порядок вызовов относительно `torch._int_mm` (down, mm, gate, up, mm), каждый слот отпущен один раз с фальшивым кольцом в настоящем `_MLP`, градиенты побитово те же с переключателем и без.
